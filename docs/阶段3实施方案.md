## 一、文档说明

本文档给出《开发计划》阶段3「模块四（拆解、可视化、再生成、验证、入库）」的可实施方案，将阶段3 的 5 个任务（3.1~3.5）连同前端改造与验收样例展开为接口、数据结构、执行流程与代码落位，并给出 M3 验收落地方式。术语与决策编号沿用《系统架构设计》一.4 与附录 A/B；接口与 schema 引用《模块详细设计》六章与《知识库与数据设计》七.1/八.1。

## 三、阶段目标

打通「模型拆解闭环：解析 → 可视化 → 再生成 → 两步验证 → 标准化入库」，验证通过后生成结构化项目（画布可编辑）（开发计划·八）。

**本阶段新定案**（实施约定，文档 v1.8 同步固化）：

1. 模块四验证接口定为 `POST /api/projects/{id}/decompose/verify`——设计文档 6.4 原路径 `/verify` 已被模块一最小命令验证占用（`backend/app/api/analysis.py:22`）；模块四全部端点收拢到 `/decompose/*` 前缀。
2. 代码再生成引擎为**后端 Python 单一确定性实现**（`ir_codegen.py`），不复用/不移植 TS `codeCompile.ts`——IR schema 与画布 GraphIR 不同，移植无收益；前端仅用 CodeViewer 展示返回代码。
3. 数值比对阈值（参照 `REPRO_DEVIATION_*` 先例）：`DECOMPOSE_NUM_RTOL=1e-5`（相对）、`DECOMPOSE_NUM_ATOL=1e-6`（绝对）、`DECOMPOSE_NUM_SEEDS="42,1337,2024"`，均可 env 覆盖。
4. IR 落 `reports/ir.json`，验证记录落 `reports/verification.json`；验证记录含 `ir_hash`（sha256 规范化 IR），PUT 调参后旧验证变 stale，入库前强校验。
5. `module_id = "mod_" + sha256(结构签名)[:16]`；签名 = 入口类 + input_spec + 节点（kind, class_name, 排序后 params 键值）+ 边（类对），不含节点 id/位置/形状（形状是推导量）；同 id 版本递增 `v1, v2, …`。
6. `source_paper_id` 本阶段置 null（project 表无 paper 关联列），后续补 project↔paper 关联再回填。

## 六、各任务详细方案

### 3.1 模型解析与 IR（依据 6.1、O4）

- **输入**：`reports/structure_report.json` 的 `module_hierarchy` + `train_flow`/`inference_flow` 定位模型定义文件与入口类。报告不存在 → 409 提示先跑模块一 `POST /analyze`。
- **处理**：agent 任务（`agent_service.run_sync(prompt, cwd=source, output_schema=IR_SCHEMA, max_turns=60, timeout_s=1800)`，prompt 内联 f-string，现惯例）解析模型定义 → 输出 IR → `validate_ir` 硬校验 → 写 `reports/ir.json`。
- **IR schema**（`reports/ir.json`）：

```json
{
  "schema_version": "1.0", "project_id": "…", "source_file": "models/resnet.py",
  "entry_class": "ResNet", "task_type": "classification",
  "input_spec": {"shape": [1,3,224,224], "dtype": "float32"}, "root_id": "n0",
  "nodes": [{"id":"n0","kind":"module|leaf|container|op","class_name":"ResNet|nn.Conv2d|nn.Sequential|add",
             "module_file":"models/resnet.py","module_path":"layer1.0.conv1",
             "params":{},"parent_id":null,"input_shape":null,"output_shape":null,
             "code_hint":null,"uncertain":false}],
  "edges": [{"from":"n0","to":"n1","tensor_shape":null}]
}
```

  字段语义：层级树由 `parent_id` 隐式表达 + `root_id` 标入口（不双写显式树）；`kind` 四类——`module`（自定义 nn.Module 子类）、`leaf`（nn.* 层）、`container`（Sequential/ModuleList，子节点经 parent_id 归属）、`op`（函数式操作 `+`/cat/F.relu，`code_hint` 存内联表达式）；`module_path` 是 named_modules 路径，为 trace 对齐运行时实例的锚点；形状 agent 能确定则填，否则 null（前端显示「未知」，由 3.2 前置的 trace 回填）。
- **prompt 要点**（O4）：只读不改文件；每 nn.Module 子类一节点；Sequential/ModuleList 展开为 container+子节点；`+`/cat/F.relu 转 op 节点；module_path 必给；拿不准标 `uncertain:true`；task_type 从结构判定（classification/regression/segmentation/detection/generation/embedding/other）。
- **validate_ir（宿主侧确定性函数）**：nodes 非空、id 唯一、parent_id/edges 引用存在、kind 合法、root_id 存在、leaf 缺 params 且无 code_hint 即不完整（6.3 拒绝生成）、op 必须有 code_hint 或白名单类名。校验不过 → 任务 failed、error 写缺失项清单、**不写 ir.json**（agent 原始输出留 `data/agent_tasks/{task_id}/result.json` 可回溯）。
- **接口**：`POST /api/projects/{id}/decompose`（触发）、`GET /api/projects/{id}/ir`（附 `verification_status: none/valid/stale`）、`PUT /api/projects/{id}/ir/nodes/{node_id}`（调参回写，仅 params）。
- **落位**：`backend/app/services/decompose_service.py`（新）+ `backend/app/api/decompose.py`（新，仿 analysis.py `_require_original` 闸门）+ `main.py`（router + lifespan 注册）+ `task_manager.TASK_TIMEOUTS` 增 `decompose: 1800`。run_record：`run_type="decompose"`。

### 3.2 trace 补形状（依据 6.1「形状缺失经 trace 补充」）

- **脚本**：`scripts/trace_shapes.py`，签名 `python trace_shapes.py <ir_json> <source_dir> <out_ir_json>`，在**项目环境**执行（`analysis_service._project_python`；环境未就绪 → 任务 failed 提示先完成环境创建）。
- **流程**：读 IR 统计形状缺失（无缺失直接跳过）→ `importlib` 动态加载 `source_file` 的 `entry_class` → `torch.randn(*input_spec.shape)` 构造输入 + `register_forward_hook` 挂子模块 → 按节点 `module_path` 定位实例回填形状（无 module_path 的按类名+出现次序兜底对齐）→ 覆盖写回 ir.json（幂等）。
- **接口**：`POST /api/projects/{id}/decompose/trace`（触发任务）。decompose 完成后若 IR 含形状缺失，任务 progress 记 `shapes_missing: true` 引导前端提示。
- **落位**：`scripts/trace_shapes.py` + decompose_service 任务 `decompose_trace`（TASK_TIMEOUTS 增 600）。run_record 同类型落库。

### 3.3 代码再生成（依据 6.3、新定案 2）

- **引擎**：`backend/app/services/ir_codegen.py`（新，纯函数无 IO/无 subprocess，输出 str）。生成策略：先 `validate_ir` 后拓扑排序；叶子白名单（nn.Conv2d/Linear/BatchNorm2d/MaxPool2d/ReLU/…，常量维护）直接实例化 `self.x = nn.X(**params)`；自定义 module 每节点输出独立类（`Decomp_{id}` 命名，`__init__` 实例化子节点、`forward` 按子树 edges 调用，**自包含不 import 源项目**）；container → `nn.Sequential(...)`；op → code_hint 内联（多入边按声明序编号变量）；变量命名 `var_{node_id}`，forward 拓扑序生成，末尾返回根节点输出。IR 不完整 → 抛 `IrIncompleteError`。
- **接口**：`POST /api/projects/{id}/decompose/regenerate` **同步返回** `{code}`（确定性毫秒级，不建任务、不落盘）。verify 任务内部自行调用引擎生成到运行目录（保证验证对象恒等于当前 IR）。
- **落位**：`backend/app/services/ir_codegen.py` + decompose.py 端点。

### 3.4 两步验证（依据 6.4、新定案 1/3/4）

- **脚本**：`scripts/verify_decompose.py`，签名 `python verify_decompose.py <ir_json> <regenerated_py> <source_dir> <out_json>`，**必须在项目环境执行**（需 torch 加载两模型）。宿主侧编排仿 `baseline_service.run_eval`：生成代码到 `ws/runs/decompose/verify/{task_id}/module.py` → `asyncio.to_thread(subprocess.run, [python, ...], cwd=source)`（Windows：命令恒 list、无 shell）。
- **判定算法**（全部 CPU + eval() + `torch.manual_seed` 固定）：
  1. **结构比对**：两模型 `named_modules()` 类型名序列逐位比对；总参数量相等 + `state_dict` 逐 key 形状比对；每组种子输入 forward 后输出 shape 相等。差异记 `diff_layers`。
  2. **数值比对**：多种子输入下逐元素相对误差 `max(|a−b|/(|b|+1e-8))` 与绝对误差 `max(|a−b|)` 双判据，阈值见新定案 3；**失败定位差异层**：递归遍历对应子模块，取最深不一致的 module_path 列表。
- **退出码约定**：比对不过（业务失败）**0 退出**（结果在 JSON——验证失败是正常业务结果）；脚本异常（模型加载失败等）非 0。
- **verification.json**（= 数据设计七.1 verification 字段内容，落 `reports/verification.json` 覆盖式）：

```json
{
  "schema_version": "1.0", "verified_at": "…", "project_id": "…",
  "ir_hash": "sha256(规范化 ir.json)…",
  "seeds": [42,1337,2024], "tolerance": {"rtol": 1e-5, "atol": 1e-6},
  "structure": {"passed": true, "layer_count": {"original": 68, "regenerated": 68},
    "param_count": {"original": 11173962, "regenerated": 11173962},
    "layer_sequence_match": true, "param_shapes_match": true, "output_shape_match": true, "diff_layers": []},
  "numeric": {"passed": true, "per_seed": [{"seed":42,"max_rel_err":0.0,"max_abs_err":0.0,"passed":true,"diff_layers":[]}]},
  "overall": "passed|failed", "failure_reason": null
}
```

- **接口**：`POST /api/projects/{id}/decompose/verify`（触发）、`GET /api/projects/{id}/decompose/verify`（最近结果）。
- **失败语义**：验证不过 → run_record（`run_type="decompose_verify"`）status=failed + error=failure_reason + artifact_path=verification.json（可检索供后续 agent 改进，6.4/架构九.4），**任务本身 success**；脚本异常 → 任务 failed。任务类型 `decompose_verify`（TASK_TIMEOUTS 增 1800）。
- **落位**：`scripts/verify_decompose.py` + decompose_service 任务。数值比对输出是张量比对，不涉及 `contracts.normalize_metrics`/CANONICAL_METRICS（模块五契约）。

### 3.5 标准化模块入库与结构化项目生成（依据 6.5、D10、D12）

- **入库前置校验**（宿主侧，返回 409/400）：ir.json 存在 → verification.json `overall=passed` → `verification.ir_hash == 当前 ir_hash`（stale → 409「请重新验证」）→ 同 module_id+version 已存在 → 409「已入库」。
- **module_id / 版本**：见新定案 5。
- **模块包落位**（数据设计七.1 目录）：`data/modules/{module_id}/{module_version}/` = `module.py`（A3 引擎再生成）+ `module.json` + `assets/`（空目录预留权重）。
- **module.json 字段与来源**：

| 字段 | 来源 |
|---|---|
| module_id / module_version | 签名/递增规则 |
| name | `entry_class` |
| description | `f"从项目 {project_id} 拆解的 {entry_class}（{task_type}）"` |
| source_project_id | 原始项目 id |
| source_paper_id | null（新定案 6） |
| task_type | IR.task_type（入库 body 可覆盖，前端下拉修正） |
| input_spec / output_spec | IR 根节点 input_spec / 根节点 output_shape 包 `{"shape":…}` |
| params_schema | 根节点 params 派生 `{参数名: {type, default}}` |
| tags | `[task_type, project.source, "decompose"]` |
| verification | verification.json 全文嵌入 |
| saved_module_compat | `{id, name, version, handles:{inputs:["in"],outputs:["out"]}, description, graph_ref: 结构化项目id}`（D10 兼容基底 SavedModule；graph 全量在结构化项目 graph.json，compat 存引用不双存） |

- **DB 写入**：module 表 INSERT（schema 已就绪）；`unified_index`：data_type=module、ref_id=`{module_id}:{module_version}`、title=name、summary=`f"{task_type} 模块 | 参数量 {param_count} | 验证通过 | 来源项目 {source_project_id}"`、tags、keywords。`knowledge_service` 增 `record_module`/`list_modules`/`get_module`（注意 module 表复合主键 `(module_id, module_version)`，`_TABLE_PK` 单主键假设需特判：专用函数拆分 ref_id；`GET /api/knowledge/items/module/{ref}` 对 module 特判）。事务：先写模块包临时目录 → DB 事务（module 表 + unified_index）成功 → rename 正式目录。
- **结构化项目生成**（D12、数据设计八.1）：`project_manager.create_project("structured", source="decompose", name=f"{原名}（拆解）", parent_project_id=原项目id)` → 写 `ws/graph.json`（**GraphIR v2**，由后端新增 `ir_to_graphir(ir)` 确定性转换：node type 统一 `"ir_node"`、data 存 `{kind, class_name, params, __shape}`、handles 由 edges 派生、parentId 镜像层级、position 留空由前端 layout）→ 项目 status 置 `ready`（structured 不适用 loading/env_ready/analyzed 流转）→ module.json `saved_module_compat.graph_ref` 回写该 id。
- **接口**：`POST /api/modules`（body `{project_id}`，触发入库任务）、`GET /api/modules`（module 表全量列表，供阶段5 拉取）；`GET/PUT /api/projects/{id}/graph`（结构化项目 graph.json 读写，require_type structured 闸门）。
- **落位**：`backend/app/api/modules.py`（新）+ decompose_service 任务 `module_ingest`（TASK_TIMEOUTS 增 300）+ knowledge_service 增量 + projects.py graph 端点。

### 3.7 前端：模型查看器（B2，依据 6.2）

- **布局**：左侧 IR 层级树（parent_id 派生，可折叠）；中部 Tab——结构图（只读 React Flow 实例，`nodesDraggable=false`，parentId 嵌套渲染容器）/ 数据流图（**复用 DiagramView.tsx** + ELK，`irToGraphIR(ir)` 转换，节点显示类名 + 形状开关）；右侧参数面板（选中节点 params 表单 → `PUT /ir/nodes/{id}`，调参成功后提示「需重新验证」）。
- **操作链**（6.3→6.4→6.5 按钮流）：`[补形状]`（IR 缺形状时）→ `[再生成]` → **CodeViewer**（Monaco 只读展示返回代码）→ `[验证]`（轮询任务 → 结果面板：结构比对表 + 数值比对 seed 行 + diff_layers 高亮 + failure_reason）→ `[入库]`（仅 overall=passed 可用；成功提示模块 id/版本与结构化项目 id → 跳转画布）。
- **IR→GraphIR 转换**：`frontend/src/utils/irAdapter.ts` 的 `irToGraphIR(ir)`（与后端 `ir_to_graphir` 同构；查看器即时渲染用前端版，后端写 graph.json 用后端版）。
- **落位**：`frontend/src/views/ModelViewerView.tsx` + `utils/irAdapter.ts`。

### 3.8 前端：结构化项目画布打开/保存（B3，依据 6.5/7.2、D12）

## 七、端到端主链路（M3 验收路径）

```
POST /api/projects (挂载样例仓库，source=local)
  → POST /{id}/env (模块一：独立环境)
  → POST /{id}/verify + POST /{id}/analyze (模块一：验证 + 结构报告)
  → POST /{id}/decompose (agent 解析 → validate_ir → reports/ir.json)
  → GET /{id}/ir (查看器渲染结构图/数据流图；缺形状 → POST /{id}/decompose/trace)
  → [PUT /{id}/ir/nodes/{n} 调参（可选）]
  → POST /{id}/decompose/regenerate (再生成代码 → CodeViewer 展示)
  → POST /{id}/decompose/verify (项目环境两步验证 → verification.json)
  → POST /api/modules (前置校验 → 模块包 + module.json → module 表 + unified_index
       → 生成结构化项目 + graph.json)
  → 项目列表 → 结构化项目 → 画布打开/修改/保存
全程 run_record 自动落库；验证不过则记录失败原因且不入库
```

## 八、M3 验收落地方式

| 验收项（开发计划·八） | 怎么测 |
|---|---|
| 真实项目拆解 → 重组 → 结构比对与数值比对均通过 → 入库 | 样例仓库挂载 → env → analyze → decompose → GET /ir（核 IR 结构）→ decompose/verify（核对 verification.json：structure 全 true、numeric 各 seed passed、overall=passed）→ POST /api/modules → 查 module 表与 unified_index（`module:{id}:{version}`）有记录 |
| 模块元信息完整落 module.json | 打开 `data/modules/{id}/{v}/module.json`：source_project_id=原始项目、task_type=classification、input_spec/output_spec 与 IR 根节点一致、tags 非空；description/verification/saved_module_compat 齐全 |
| 验证通过生成结构化项目，可画布打开并修改 | 入库后查 project 表出现 structured 项目（parent_project_id 正确、graph.json 存在）→ 前端项目列表打开画布 → ResNet 结构渲染（层级嵌套 + 跳跃边）→ 改某 conv 节点 kernel_size → 保存 → 刷新重开仍在（核对 graph.json） |
| 验证失败场景：失败原因被记录且不入库 | 构造失败：`PUT /ir/nodes/{conv1}` 把 out_channels 64→48 → regenerate → verify → verification.json overall=failed、failure_reason 记录、diff_layers 定位到具体层（module_path）→ 确认 module 表无新行、无新结构化项目 → 前端验证面板展示失败原因、入库按钮禁用 |

## 九、风险与应对

- **agent 解析质量是最大不确定性（O4）** → prompt 要点（module_path 锚点/uncertain 标注/不臆造）+ validate_ir 硬校验 + trace 形状兜底 + **数值比对硬闸门**（任何解析错误都会在结构/数值比对暴露并定位到层）；先样例后 GEARS 渐进打磨。
- **数值比对环境** → 验证脚本强制 CPU + eval() + 同种子；环境未就绪明确报错「先跑通模块一」（先例 baseline_service）；Windows 子进程命令一律 list 形式、无 shell。
- **前端改造量（无路由无 API client 是现状最大缺口）** → 最小方案（顶层 state 切换不引 react-router、FlowEditor 仅 props 注入、查看器复用 DiagramView/CodeViewer/ELK）；FlowEditor initialGraph 注入是风险点，用 `key` 重挂载隔离。
- **module 复合主键** → 专用存取函数 + get_item 特判，不泛化改动通用代码。
- **解析大模型的轮数/超时** → decompose max_turns=60/timeout=1800（样例 ~70 节点、GEARS ~百级）；结构化输出失败重试 3 次已内建。

### 11.2 与方案的偏差记录（实际结构）

1. **前端 api/ 未拆子文件**：方案 3.6 的 `projects.ts`/`decompose.ts`/`modules.ts`/`tasks.ts` 全部内联进 `client.ts` 单文件（体量可控，单文件更简）。
2. **`hooks/useTaskPolling.ts` 未建**：轮询按视图内联（ProjectListView 3s、ModelViewerView 2s setInterval），未抽象独立 hook。
3. **IR 节点注册方式变更**：方案 3.8 的 `nodes/ir/IrNode.tsx` + registry `"ir_node"` → 实际 `nodes/IrNode.tsx` + `nodeTypes["ir"]`（不属 LAYER_REGISTRY，编辑器守卫已审计：`ir` 类型不会崩画布）；画布代码生成钩子空实现未做（本阶段无调用点，留阶段4）。
4. **views/ 多一文件**：方案只列 ProjectListView/ModelViewerView，实际新增 `CanvasProjectView.tsx`（画布页独立视图）。
5. **graph.json 布局后置**：方案「position 留空由前端 layout」→ 实际后端 `ir_to_graphir` 确定性布局（顶层按最长路径分层 320×150、子节点两列网格 240×100、父节点 layout_hint），前端 `irAdapter.ts` 同构移植供查看器即时渲染；node type 为 `"ir"`（非 `"ir_node"`），data 用 display{title,params,shape}+handles。
6. **新增两个方案外脚本**：`scripts/_model_loader.py`（入口类实例化兜底）、`scripts/m3_acceptance.py`（M3 验收驱动，纯标准库，含 full/fail/light 三模式）。
7. **样例仓库补充**：ResNet 构造参数带默认值（`block=BasicBlock, num_blocks=(2,2,2,2), num_classes=10`），使入口类可无参实例化，适配 _model_loader。
